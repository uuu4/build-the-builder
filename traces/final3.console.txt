The phone agent is built and deployed. It passed every example conversation I replayed against it. There are no practice customers for this case, so I couldn't run the scored test. Instead I replayed the six example scenarios plus several edge cases from the bank's test customers over chat.

**What's in `out/final3/`**
- `tools.openapi.json`: written from the service contract. It has the seven services at the mock URL, and I checked it against the mock with real calls.
- `rules.md`: every rule with where it lives, plus how I settled the conflicts between documents.
- `gen.py`, which generates `workflow.json` (40 nodes, lint clean).
- The `chat-*.json` replay files.

This isn't a collections call, so the kit's ready-made front and negotiation parts didn't fit. I built the graph myself:
- **Debt reading:** built in code from what the bank's services return. Amounts are read in Turkish words, dates as day, month and year, last four digits one by one, currencies by their full names. The sentence order and wording follow the 8 October analysis.
- **Bank-required sentences:** spoken word for word, never left to the model.
- **E-mail and statement-week changes:** made only after an explicit "evet". They are not retried, because both have side effects. "Sent" or "changed" is said only after the bank confirms success.
- **Errors:** "no valid card" goes to the main menu, a service failure goes to an agent.

**Replays that matched the expected behaviour**
- Examples 1 to 6. In example 4 a hedged "ok, the latest one" isn't taken as a yes; the agent asks the send question again. In example 5 "Olur herhalde" isn't taken as a yes either.
- Two cards with the same name and last four digits: the agent asks for the last six digits, then the full number.
- Shared statement: both cards are read and the "this will also affect your other card" line is said.
- Card list returns 500: transfer to an agent.
- E-mail service returns 500: transfer to an agent if the caller asks for e-mail.
- Out-of-scope question: "do you want the main menu?", then continue if they say no.
- Payment request: transfer to an agent.

**Platform findings that shaped the build**
- An API node can't be the first node: its call never runs. I start with a code node.
- A spoken line on the first API node broke the chat replay with a 504 timeout, so I removed it.

**Choices you may want to check** (logged as `uncertain_default`)
- **Someone else's card:** example 5 says go to the main menu with a security sentence; the analysis says send them back to the IVR login. I followed the example.
- **E-mail service failure:** the e-mail option isn't offered. If the caller asks for it anyway, they get the "can't do this now, transferring you to an agent" sentence.

**Known gaps**
- If the caller names their card in their very first sentence, the agent still asks which card.
- In example 5, the call ends right after the week change. A later question about a spouse's card is never heard.
- The "three silences ends the call" rule relies on the model recognising silence; it isn't counted in the graph.
